# Audio Book

A static website (`player/`, published with GitHub Pages) that turns PDF/EPUB/TXT books into MP3 audiobooks **in the browser** and plays them. There's also a command-line converter (`converter/audiobook.py`). The owner is not a programmer: explain things in plain words, avoid jargon, and give click-by-click steps for anything they have to do on GitHub.

## How the website works

- `book-text.js` reads the book (PDF.js for PDF, JSZip for EPUB) and splits it into chapters. For PDFs it rebuilds paragraphs from indents, gaps and short last lines, and drops running headers and footers. Its rules mirror `converter/audiobook.py` (the converter can't see indents, but does drop headers); keep the two in step.
- `speech-text.js` prepares text for the voice ("Natural" delivery): rewrites things Piper reads badly ($10M, Chapter IV, U.S., 10:30 a.m., big numbers), splits sentences, and plans pauses and pace. Headings are spoken together with the next sentence, because several voices mumble a heading on its own; the worker then widens the gap after the heading. It's plain functions, tested with `node --test tests/*.test.js`.
- Piper's expression settings (noise_scale, noise_w) barely change the pitch and add mistakes, so they stay at the voice defaults. Norman and John (LibriVox-trained) drag out "Chapter One"; `synthesizeChecked` remakes overly long sentences faster instead of dropping them.
- `convert.js` stores the chapter texts in IndexedDB (`jobs` store), then runs several `tts-worker.js` workers. Each loads a Piper voice from `player/voices/` with ONNX Runtime Web, phonemizes with piper-phonemize (WASM), and encodes MP3 with lamejs. Finished chapters are saved straight into the library, so playback can start early and making can resume after a reload.
- `app.js` holds the library (IndexedDB `books` + `files`), the player, bookmarks/quotes (`book.marks`), listening stats (localStorage), and the zip download. Use `db.updateBook` for read-modify-write so the converter and player don't overwrite each other.
- Read along: the voice-clone tool saves a timing file per chapter next to its MP3 (`01 - Title.json`: `text`, `sentences` and `words` as `[first char, last char + 1, start seconds]`; word times come from Whisper aligning the book's own words to the audio) and names it in `book.json` (`chapters[].text`). Import stores it as `textFileId` (published books: `textUrl`). `read-along.js` is the pure timing/layout/search logic (tested with node); `reader.js` is the view. The highlight follows `Reader.loop()` (requestAnimationFrame) plus every `timeupdate`, because hidden pages get no animation frames. Only scrolls after the listener's own wheel/touch/key/pointer turn off following; reflows from font changes must not.
- A chapter can be part of a file (M4B with chapter marks): `{ url, start, end }` in seconds. All player times are within the chapter: use `chapterTime()`, `chapterLength()` and `seekTo()`, never `audio.currentTime` directly. The next chapter in the same file keeps playing without reloading.
- `desktop/` is the Windows app (Electron). It shows this same player, copied in by `desktop/scripts/copy-player.js`; `player/desktop.js` adds the desktop parts only when `window.desktop` exists (books on disk with `onDisk: true` and `app://disk/` URLs, library folders, drop, mini player, commands from the menu/taskbar/tray). Keep the player working on both.
- Design ("Studio"): dark first, light under `prefers-color-scheme: light`. Fonts are vendored (Inter for the app, Literata for the Serif reading font, OpenDyslexic). Each book lends its cover's main colour (`toneOf()` in app.js samples the cover; `applyTone()` sets `--tone-h` / `--tone-s`) to elements with the `toned` class (the player, the player bar, the Continue listening card), whose `--stage-*`, `--on-stage*` and `--play-*` colours are worked out per element. Layout: sidebar on wide screens, top bar plus bottom tab bar under 900px; the player is two columns from 1100px (stage | side panel with Read along / Chapters / Bookmarks, `setPanel()`), one column below, with a compact reading mode and a Focus mode (`setFocus()`).
- `service-worker.js`: network-first for app files, cache-first after first use for `voices/` and `vendor/`, never `books/` or range requests. Bump `CACHE` when changing which files are precached.
- Plain HTML/CSS/JS with no build step and no CDN. Third-party code is vendored in `player/vendor/` (see its README for versions and licences). Keep it that way.

## Testing

- Serve with `npx http-server player -p 8766` or `node tools/serve-player.js` (it needs range requests; `python -m http.server` breaks audio seeking), then drive it with Playwright. Chromium is preinstalled. `serve-player.js --mount /test=<folder>` serves a test book alongside, so its files can be fetched and passed to `importItems()` the way **Add a folder** does.
- Converter tests: `pytest -q`. The end-to-end test needs `espeak-ng` and `ffmpeg`. Speech text and read-along tests: `node --test tests/*.test.js` (on Windows PowerShell, list the files: the glob isn't expanded).

## Command-line converter

`python converter/audiobook.py <file>` writes to `player/books/<slug>/` and rebuilds `player/books/index.json`. The site then lists those books as "Online". Its default voices (edge-tts) need network access to `speech.platform.bing.com`. If a cloud session blocks that host, tell the owner how to allow it (environment settings → Network access → Allowed domains) instead of quietly switching to `--engine espeak`. Remind the owner that published books are public on a free GitHub account.
